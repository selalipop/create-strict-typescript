# TanStack Start

This project uses TanStack Start (meta-framework over Vite + TanStack Router) for server rendering and routing.

## Routing

File-based routing from `src/routes/`. The auto-generated `src/routeTree.gen.ts` registers every `createFileRoute("/path")(...)` — **do not edit `routeTree.gen.ts` by hand**, it's regenerated by the Vite plugin on dev/build, and also by `pnpm routes:generate` explicitly.

Route filename conventions:
- `src/routes/index.tsx` → `/`
- `src/routes/about.tsx` → `/about`
- `src/routes/blog/$slug.tsx` → `/blog/:slug` (param)
- `src/routes/api/v1/rpc.$.ts` → `/api/v1/rpc/*` (catch-all — the literal `$` in the filename matters)
- `src/routes/__root.tsx` → root layout (wraps everything)

After adding or renaming a route file, re-run `pnpm routes:generate` (or keep `pnpm dev` running and it regenerates automatically). If TypeScript complains that `createFileRoute("/foo")` is `not assignable to parameter of type 'undefined'`, `routeTree.gen.ts` is stale.

## Data loading — pick the right tool

Three overlapping mechanisms. Rules of thumb:

| Use | When |
|---|---|
| **`loader`** in `createFileRoute` | Data needed for SSR / prerender, cache-controlled via `headers()`. Renders before the component mounts. |
| **`createServerFn`** | Imperative server-side logic that runs on demand from the client (not necessarily on page load). Typed, no manual fetch. |
| **oRPC procedure** | Anything reused across multiple components or involving validation / auth middleware. The default for most data reads. |

Anti-pattern: making an oRPC call from a loader. If SSR needs the data, call the server function directly (`await someServerFn(...)`) from the loader.

## Root layout

`src/routes/__root.tsx` is where the `<html>` shell lives, plus `<HeadContent />` (renders `head()` output) and `<Scripts />` (SSR hydration). Keep it minimal — push provider logic out to wrapper components so you don't slow down every route.

`QueryClientProvider` lives in `__root.tsx` so all routes share a single `QueryClient` (idiomatic for React Query).

## Vite plugin ordering (don't reorder without reason)

`vite.config.ts` orders `tanstackStart(...)` **before** `viteReact(...)`. TanStack's transforms (server-fn extraction) must run before React's JSX transform. Same applies to `nitro()` being conditional on `!isSpaMode` — when `VITE_SPA_MODE=true` (Capacitor builds), Nitro is skipped.
